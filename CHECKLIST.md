# Чеклист ручной проверки

Пройдите разделы по порядку: в каждом пункте указано действие и то, что должно получиться. Отмечайте `[x]`.
Если результат другой — запишите номер пункта и что увидели.

## 0. Подготовка

**Запуск (один раз):**

```bash
docker compose up -d postgres redis          # в корне проекта
cd backend
cp .env.example .env                         # если .env ещё нет
pnpm install
pnpm prisma generate && pnpm prisma migrate deploy
pnpm prisma db seed                          # демо-пользователи
pnpm start:dev                               # API: http://localhost:4000/api/docs
# в другом окне терминала:
cd frontend
cp .env.example .env.local
pnpm install
pnpm dev                                     # сайт: http://localhost:3000
```

Если в `backend/.env` не задан `SMTP_HOST`, письма не уходят, а печатаются в окне API (там же ссылка подтверждения).
Для проверки push в `backend/.env` должны быть `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
(ключи: `cd backend && pnpm exec web-push generate-vapid-keys`).

**Готовые аккаунты (после seed):**

| Роль | Email | Пароль |
| --- | --- | --- |
| Менеджер (Супер ЛК) | `admin@greenangle.local` | `admin12345` |
| Компания по привозу | `broker@autopodbor.local` | `broker12345` |
| Физ.лицо | `smirnov@example.local` | `individual12345` |

**Нужно для проверки:** два браузера или окно + окно инкогнито (чтобы одновременно быть клиентом и менеджером);
Chrome для push; почтовый ящик, на который можно зарегистрироваться (или окно API, где печатаются письма).

> Вход ограничен: 5 неверных попыток за минуту на связку «адрес + email». Если упёрлись, подождите минуту.
> Проверка VIN на главной — 10 запросов в минуту с одного адреса.

- [ ] Сайт открывается на `http://localhost:3000`, Swagger — на `http://localhost:4000/api/docs`, `http://localhost:4000/api/v1/health` отвечает `ok`.

### Проверка этапа по VIN на главной

Для проверки заведите машину (раздел 7.3) или возьмите VIN любой машины из Супер ЛК.

- [ ] Верный VIN (17 символов): карточка с названием машины, этапом, полосой прогресса и датой обновления; владельца и файлов не видно.
- [ ] Тот же VIN в нижнем регистре или с пробелами по краям находится так же.
- [ ] Меньше 17 символов: «Нужен VIN из 17 символов» и сколько введено.
- [ ] Неизвестный VIN: «Машины с таким VIN у нас нет».
- [ ] В поле нельзя ввести кириллицу, дефисы и спецсимволы (убираются), больше 17 символов не вводится.
- [ ] Больше 10 проверок за минуту: «Слишком много проверок. Подождите минуту».
- [ ] Удалённая машина (раздел 7.7) больше не находится.

## 2. Регистрация и подтверждение почты

- [ ] «Регистрация» → тип «Компания по привозу»: поля название, ИНН, телефон, email, пароль, согласие.
- [ ] Отправка пустой формы подсвечивает все ошибки и ставит курсор на первое поле.
- [ ] Проверки: ИНН не 10 и не 12 цифр, телефон короче 11 цифр, email без `@`, пароль короче 8 символов, нет галочки согласия — у каждого своя ошибка.
- [ ] Переключение на «Физ.лицо» меняет поля (ФИО вместо названия и ИНН), ошибки старых полей пропадают.
- [ ] Корректная отправка: окно «Проверьте почту» с вашим адресом; «отправьте его ещё раз» присылает письмо снова.
- [ ] Письмо пришло (или напечатано в окне API), оформление понятное, есть ссылка вида `http://localhost:3000/verify-email?token=…`.
- [ ] До подтверждения вход с верным паролем отвечает «Почта не подтверждена» и предлагает отправить письмо ещё раз.
- [ ] Ссылка из письма: «Почта подтверждена», кнопка «Войти» открывает окно входа.
- [ ] Повторный переход по той же ссылке снова показывает «Почта подтверждена» (без ошибки).
- [ ] Испорченная ссылка (измените пару символов в `token`) или без `token`: «Ссылка недействительна» и форма «Отправить письмо ещё раз».
- [ ] Регистрация с уже занятым email выглядит так же, как успешная (приложение не выдаёт, что адрес занят); второго аккаунта не появляется.
- [ ] Вход после подтверждения: компания попадает в «Заказанные машины», физлицо — в «Мои машины».

- [ ] Обновление страницы (F5) в кабинете оставляет вошедшим; закрытие и открытие вкладки — тоже.

## 4. Компания по привозу (`broker@autopodbor.local`)

### Машины

- [ ] «Заказанные машины»: карточки с названием, VIN («ещё не заполнен», если нет), бейдж этапа, полоса из 13 делений, «Обновлено дд.мм».
- [ ] Фильтры «Все / В пути / Готовы к выдаче» показывают правильные числа; число рядом с вкладкой в меню совпадает с «Все».
- [ ] Поиск по части VIN или названия (без учёта регистра) отфильтровывает; «Ничего не нашлось» при пустом результате; пока нет ни одной машины — «Здесь пока пусто» и кнопка «Перейти к заявкам».
- [ ] Цвет бейджа: жёлтый, если текущий этап ждёт вложение (фото, видео, файл, номер) и его ещё нет; синий — если вложение есть или не требуется; зелёный на 13-м этапе.
- [ ] Карточка машины: 13 этапов с пометками «Пройден / Текущий этап / Впереди», у будущих и текущего без вложения — «Нужно: …» или «Ожидается …».
- [ ] Вложения этапов — чипы «Фото», «Фото 2», «Файл», «Видео», «№ декларации»; клик открывает файл в новой вкладке.
- [ ] Справа: «Прогресс» с подсказкой («Менеджер прикрепит фото…» либо «Следующий этап — …», на 13-м — «Машина готова к выдаче»), «Заказ создан», «Обновлено», «Вложений».
- [ ] «Диалог по заявке» есть только у машин, созданных из заявки, и ведёт в диалог; у вручную добавленных машин строки нет.

### Уведомления клиенту (только у компаний)

- [ ] В карточке блок «Уведомлять клиента»: поле email и галочка.
- [ ] Включить галочку без email: «Укажите email клиента, чтобы включить письма».
- [ ] Неверный формат email — ошибка; верный email + галочка → «Письма клиенту включены».
- [ ] После перезагрузки значения сохранены. Смена email без галочки ничего не включает.
- [ ] Менеджер двигает этап вперёд — на этот email приходит письмо (раздел 8.1); при выключенной галочке не приходит.

### Заявки и диалог

- [ ] «Заявки» → «Новая заявка»: марка и модель, год (список), бюджет, комментарий. Пустые марка или бюджет — ошибки.
- [ ] После отправки открывается диалог; первое сообщение пишется автоматически: «Новая заявка: … Бюджет … ₽.» и комментарий.
- [ ] В списке заявок: название «Модель, год», «Бюджет … · дата», последнее сообщение, бейдж статуса; «Всего заявок: N».
- [ ] В диалоге: шапка с названием, бейджем, бюджетом, типом клиента и датой; сообщения своих справа, чужих слева, служебные строки по центру.
- [ ] Отправка текста работает (Enter и кнопка); пустое сообщение не отправляется.
- [ ] Скрепка: выбор файла (фото, видео, pdf/doc/docx/xls/xlsx/zip) — чип с «загрузка…», затем обычный; крестик убирает вложение; кнопка «Отправить» заблокирована, пока файл грузится.
- [ ] Недопустимый тип (например, `.exe`) или слишком большой файл: понятное сообщение, вложение не добавляется.
- [ ] Кнопка со звеном: поле ссылки; ссылка без `http://` или `https://` — ошибка; верная добавляется чипом «Ссылка на объявление».
- [ ] В отправленном сообщении чипы файла и ссылки открываются в новой вкладке.
- [ ] Не больше 10 вложений в одном сообщении.
- [ ] «Показать ранние сообщения» появляется в длинном диалоге (больше 50 сообщений).
- [ ] Когда менеджер одобрил заявку: зелёная плашка «Заявка закрыта… Открыть заказ», писать в диалог больше нельзя (поля ввода нет); при отклонении — жёлтая плашка «Заявка отклонена менеджером».
- [ ] Если машину позже удалили (раздел 7.7): плашка «Машину по ней удалил менеджер», в диалоге строка «Менеджер удалил машину.».

## 6. Диалог и непрочитанное (двое: клиент и менеджер в разных окнах)

- [ ] Менеджер пишет в диалог — у клиента на вкладке «Заявки» появляется красный значок с числом непрочитанных; пока диалог закрыт он растёт с каждым сообщением.
- [ ] Клиент открывает диалог — значок уменьшается на число прочитанных сообщений; если диалог уже открыт, новые сообщения читаются сразу и значок не растёт.
- [ ] Если непрочитанных нет — значка нет.
- [ ] Сообщения в открытом диалоге появляются у собеседника сами, без обновления страницы.
- [ ] У менеджера «Входящие заявки» показывают число ждущих ответа (оранжевый значок); оно растёт, когда клиент пишет, и уменьшается, когда менеджер отвечает.
- [ ] Один менеджер прочитал диалог — у второго менеджера (другой аккаунт) он остаётся непрочитанным.

## 7. Супер ЛК (`admin@greenangle.local`)

### 7.1 Все машины

- [ ] Таблица: «Машина, VIN, Владелец, Статус, Обновлено»; у машин без VIN в колонке жёлтое «Заполните VIN».
- [ ] Фильтры «Все / Компании по привозу / Физ.лица» с числами; поиск по VIN (часть VIN, регистр не важен); «Машин с таким VIN не найдено».
- [ ] Клик по строке открывает карточку.

### 7.2 Очередь заявок

- [ ] «Входящие заявки»: фильтр «Ждут ответа / Все» с числами; сверху — ждущие ответа; у них оранжевая метка «Ждёт ответа».
- [ ] В строке: клиент и его тип, «Модель, год», бюджет, бейдж статуса, последнее сообщение с автором («Клиент / Менеджер / Система») и временем.
- [ ] Когда ждущих нет: «Все ответили. Новых заявок нет.»

### 7.3 Добавить машину

- [ ] «Добавить машину»: марка/модель/год, VIN (автоматически заглавные латинские и цифры, счётчик «N из 17»), тип владельца, имя, стартовый этап.
- [ ] Пустые поля и VIN не из 17 символов — ошибки.
- [ ] Под полем владельца перечислены уже существующие клиенты.
- [ ] Новый владелец: машина создаётся, появляется новый клиент; владелец без логина пока не видит её (учётка создаётся в разделе 11).
- [ ] Имя и тип совпали с существующим клиентом (точно, без учёта регистра): машина достаётся ему, второй клиент не создаётся (проверьте в Swagger `GET /admin/clients`).
- [ ] Занятый VIN: ошибка под полем VIN, машина не создаётся.

### 7.4 Карточка машины

- [ ] Шапка: название, VIN, тип и имя владельца, бейдж этапа.
- [ ] Если VIN пуст — жёлтая плашка и форма «VIN»: меньше 17 символов — ошибка; верный VIN сохраняется, форма пропадает, клиент видит VIN.
- [ ] «Сменить статус»: список всех 13 этапов; по умолчанию следующий.
- [ ] Этапы без вложения (1, 5, 11): подсказка «вложение не нужно», сохраняется сразу.
- [ ] Этапы с фото (3, 6, 7, 9, 12, 13): область «Перетащите фото или нажмите» — выбор и перетаскивание файлов; без файла «Для этого статуса нужно фото».
- [ ] Этап 2 (файл) и 8 (файл): принимает pdf/doc/docx/xls/xlsx/zip. Этап 4 (видео): mp4/mov/webm. Файл другого вида отклоняется.
- [ ] Этап 10: поле «Номер декларации», без него — ошибка.
- [ ] Комментарий для клиента необязателен; если у машины есть заявка, уходит в диалог сообщением менеджера вместе с вложениями.
- [ ] После сохранения: тост «Статус … сохранён», этап и бейдж обновились, в диалоге клиента строка «Статус машины: …».
- [ ] Откат на более ранний этап не требует вложений (исправление ошибки); письмо клиенту при откате не уходит.
- [ ] Повторное сохранение того же этапа с новым файлом добавляет вложение.
- [ ] Клиент у себя видит новый этап и вложения без перезагрузки.

### 7.5 Ответ на заявку

- [ ] Открыть заявку из очереди: шапка с клиентом, переписка, поле ответа, скрепка и звено (как у клиента).
- [ ] Первый ответ менеджера переводит заявку «Новая» → «В диалоге».
- [ ] «Отклонить»: заявка получает статус «Отклонена», в диалоге системная строка, писать нельзя.
- [ ] «Одобрить и создать заказ»: статус «Одобрена», зелёная плашка с «Открыть заказ», создана машина на этапе 1 «Ожидает оплату» без VIN, в диалоге строка об одобрении; у клиента появилась машина.
- [ ] Повторное одобрение или отклонение уже закрытой заявки не создаёт вторую машину (кнопки пропадают).

### 7.6 Закрытые заявки

- [ ] У одобренной и отклонённой заявки нет поля ввода; переписка читается.

### 7.7 Удаление машины

- [ ] В карточке «Удалить машину» открывает окно «Удалить машину? … пропадёт у владельца вместе со всеми вложениями».
- [ ] «Отмена» закрывает окно, машина остаётся.
- [ ] «Удалить»: переход в «Все машины», тост «Машина удалена», машины в таблице нет, число в меню уменьшилось.
- [ ] У владельца машина пропала из списка (в открытом кабинете — сама); карточка по прямой ссылке возвращает в список.
- [ ] Заявка, из которой создана машина, остаётся «Одобрена», в диалоге строка «Менеджер удалил машину.».
- [ ] Файлы удалённой машины недоступны по старым ссылкам.
- [ ] VIN удалённой машины можно завести заново (раздел 7.3).
- [ ] Публичная проверка по VIN удалённую машину не находит.

## 8. Уведомления

### 8.1 Письма о смене статуса

Проверяется на движении этапа вперёд (раздел 7.4).

- [ ] Физлицо с включённым переключателем получает письмо на свой email: название нового этапа и ссылка на карточку.
- [ ] Компания: письмо уходит на email клиента из «Уведомлять клиента» (если включено), без ссылки на кабинет; самой компании письмо не приходит.
- [ ] Не приходят: откат назад, повтор того же этапа, отклонение, письма о сообщениях диалога (для них push).
- [ ] Если почта недоступна, смена статуса всё равно сохраняется.

### 8.2 Push в браузере (Chrome, `http://localhost:3000`)

- [ ] В левом меню есть «Включить уведомления» (нет ключей VAPID на сервере или браузер не поддерживает — кнопки нет).
- [ ] Нажатие запрашивает разрешение браузера; после разрешения кнопка «Выключить уведомления», тост «Уведомления включены».
- [ ] Запрещённое в браузере разрешение: кнопка остаётся, нажатие объясняет, где разрешить.
- [ ] Менеджер пишет клиенту — у клиента всплывает уведомление «Новое сообщение по заявке «…»» (текста сообщения в нём нет); клик открывает именно этот диалог.
- [ ] Клиент пишет — уведомление получает менеджер, ответивший в этой заявке последним; пока никто не отвечал — все менеджеры сразу.
- [ ] Автору своё сообщение не приходит; чужие клиенты ничего не получают.
- [ ] Эскалация: поставьте в `backend/.env` `PUSH_FALLBACK_MINUTES=1`, перезапустите API; клиент пишет, ответственный менеджер молчит — через 1–2 минуты уведомление «Заявка «…» ждёт ответа» получают остальные менеджеры (один раз на сообщение). Верните значение 60.
- [ ] «Выключить уведомления» перестаёт присылать; выход из кабинета тоже отключает уведомления этого браузера.
- [ ] На узких экранах (до 860 пикселей) кнопки уведомлений нет — это ограничение макета.

> Доставка через настоящий сервис push Google проверена только на уровне тестов и показа уведомления;
> пункты 8.2 — единственное место, где нужна ваша проверка в живом Chrome.

## 9. Живые обновления (два окна)

- [ ] Менеджер меняет этап — карточка и список машин клиента обновляются сами.
- [ ] Новая заявка клиента появляется в очереди менеджера без перезагрузки, число в меню растёт.
- [ ] Одобрение заявки: у клиента появляется машина, плашка в диалоге меняется.
- [ ] Удаление машины менеджером убирает её из открытого списка клиента.
- [ ] Остановите API на 10–20 секунд и запустите снова: сайт переподключается, данные догружаются, ошибок на экране нет.

## 10. Файлы и хранилище

- [ ] Загруженные файлы лежат в `backend/data/uploads` (`UPLOAD_DIR`).
- [ ] Ссылки на скачивание временные: скопируйте ссылку из чипа, откройте — файл открывается; через час (`DOWNLOAD_URL_TTL_SEC`) старая ссылка перестаёт работать, на странице свежая берётся при загрузке.
- [ ] Лимиты: фото до 20 МБ, видео до 500 МБ, файлы до 50 МБ.
- [ ] Возврат на S3: `docker compose --profile s3 up -d minio`, в `.env` `STORAGE_DRIVER=s3` и `S3_*` из `.env.example`, перезапуск API — новые вложения грузятся и открываются так же (консоль MinIO — `http://localhost:9001`, `minio` / `minio12345`).

## 11. Только через API (Swagger `http://localhost:4000/api/docs`)

Экранов для этого нет. В Swagger нажмите «Authorize» и вставьте `accessToken` менеджера (получить: `POST /auth/login`).

- [ ] `GET/POST /admin/clients`, `GET/PATCH/DELETE /admin/clients/{id}`: поиск, фильтр по типу, создание, переименование; удалить клиента с пользователями, машинами или заявками нельзя (409).
- [ ] `POST /admin/users`: создание логина подборщику, физлицу или сотруднику (`clientId` обязателен для подборщика и физлица); дубль email — 409; пользователь сразу может войти.
- [ ] `PATCH /admin/users/{id}` `{isActive:false}`: пользователь больше не входит, его сессия закрывается (раздел 3); себя деактивировать нельзя.
- [ ] `POST /admin/users/{id}/reset-password`: без тела возвращает временный пароль один раз; старые сессии пользователя закрываются.
- [ ] `POST /requests/{id}/voice-upload-url` и `POST …/messages` с `type: "VOICE"`: голосовые сообщения работают через API (экрана в сайте нет); показываются чипом «Голосовое».
- [ ] `GET /health` и `GET /health/ready` (проверяет БД и хранилище; при недоступном Redis показывает `degraded`).

## 12. Безопасность и устойчивость

- [ ] Клиент по прямому запросу к API не видит чужого: `GET /api/v1/vehicles/<id чужой машины>` с вашим токеном — 404 (не 403).
- [ ] Клиентский токен на `/api/v1/admin/...` — 403; без токена — 401.
- [ ] В ссылке на объявление нельзя отправить `javascript:` (форма не принимает; API отвечает 400).
- [ ] Сообщение с HTML (`<script>alert(1)</script>`) показывается как текст.
- [ ] Заголовки: `curl -I http://localhost:4000/api/v1/health` содержит заголовки безопасности (helmet).
- [ ] CORS: запрос с чужого Origin (`curl -H "Origin: http://evil.example" -I …/health`) не получает разрешающих заголовков.
- [ ] Лимит запросов: 600 в минуту на адрес (проверять не обязательно); вход и проверка по VIN проверены выше.
