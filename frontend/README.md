# Green Angle — фронтенд

Личный кабинет HUATECH: лендинг, кабинеты компании по привозу и физ.лица, Супер ЛК менеджера.
Дизайн берётся только из `../huatech-handoff/` (папку не менять). Сейчас это перенос макета без бэкенда:
данные демонстрационные, лежат в браузере. Связка с API — следующий шаг, см. `../PLAN.md` §10.

## Стек

Next.js 16 (App Router, `src/`), React 19, TypeScript, SCSS (`sass`), ESLint. Пакетный менеджер — pnpm.

## Команды

```bash
pnpm install
pnpm dev          # http://localhost:3000
pnpm build && pnpm start
pnpm lint
```

## Структура

```
src/
  app/                    маршруты
    page.tsx              главная (лендинг; вошедший пользователь уходит в свой кабинет)
    (cabinet)/            каркас кабинета (меню слева + main), доступ только после входа
      cars, cars/[id]               клиент: машины
      requests, requests/[id]       клиент: заявки и диалог
      admin/cars, admin/cars/[id]   Супер ЛК: все машины, смена статуса
      admin/requests, admin/requests/[id]  Супер ЛК: очередь заявок и диалог
  components/
    ui/                   Icon, Badge, Progress, Chip, Seg, Field (+ useForm), Modal, Toast
    modals/               вход, регистрация, новая заявка, добавление и удаление машины
    landing/              секции лендинга
    cabinet/              меню, списки, карточки, диалог, форма смены статуса
  lib/                    типы, справочники (13 статусов), seed, store, форматирование, навигация
  styles/
    tokens.scss           дизайн-токены (из design-system/tokens.css), светлая и тёмная тема
    app.scss              стили макета (всё из <style> index.html, кроме токенов), без изменений
```

## Данные и состояние

- Хранилище — `src/lib/store.ts`: модуль-синглтон + `useSyncExternalStore`. Данные, роль и признак входа
  пишутся в `localStorage` (ключ `ga-proto-v2`, как в макете); фильтры, поиск, черновики вложений — только в памяти.
- Первый кадр всегда строится из seed (совпадает с серверным HTML), после гидратации подтягивается `localStorage`.
- Вход «любым логином и паролем», переключатель ролей «Смотреть как» и «Сбросить демо-данные» — демо-механики
  макета, на них стоит пометка в `../PLAN.md` §10; при подключении API они уйдут.

## Маршруты и доступ

Страницы открываются по тем же правилам, что в макете: гость видит лендинг на любом адресе; клиент не попадает
в `/admin/*`, Супер ЛК — в `/cars` и `/requests` (уводит на стартовый раздел роли); чужая машина или заявка у клиента
ведёт обратно в список; у Супер ЛК неизвестный id показывает карточку «Этого раздела нет в текущем кабинете».

## Сверка с макетом

CSS и токены совпадают с макетом: `app.scss` — построчно, токены — по вычисленным значениям во всех сочетаниях
светлой/тёмной темы и `data-theme`. Экраны сверялись попиксельно с `huatech-handoff/prototype/index.html`
(Playwright, фиксированное время, `prefers-reduced-motion`): лендинг, окна входа и регистрации с ошибками, все
экраны трёх ролей, диалог, смена статуса, добавление и удаление машины — на 1280×800 и 390×844, светлая и тёмная
тема. Скрипты сверки лежат вне репозитория.

Намеренные отличия поведения (внешний вид тот же):

- страницы получили настоящие адреса вместо одного `index.html` (работают «назад» и прямые ссылки);
- DOM не пересоздаётся при каждом действии, поэтому фокус остаётся на нажатой кнопке (в макете терялся),
  а прокрутка полосы фильтров и страницы сохраняется средствами браузера.
